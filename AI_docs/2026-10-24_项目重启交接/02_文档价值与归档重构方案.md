# 文档价值、阅读顺序与归档重构方案

核查日期：2026-10-24。目标是让你和师兄先读结论，再按需进入原理与实验证据。**本轮提供结构与逐文件分类建议，不批量移动、删除历史文档。**

## 1. 文档规模与问题

main 的 AI_docs 有 **67 篇受 Git 跟踪的 Markdown**。合并检查全部现存 branch tips 后，共 **97 个不同路径、112 个内容版本**。同一路径的多个版本以及历史改名造成重复，不能简单把数字相加理解为 112 篇独立研究成果。

完整逐版本清单见 [document_inventory.csv](evidence/document_inventory.csv)，逐篇阅读/归档建议见 [文档目录表](evidence/文档逐篇目录.md)。其中记录 blob SHA、所在分支、行数、建议位置及用途；保留了 branch-only 文档，避免只整理 main 而漏掉伪标签和 RHL 迁移报告。

主要问题：

- “idea构思与实验设计”混放提案、已完成结果、冻结决策和新手教学。
- “代码理解”与“论文精读”有多份覆盖相同内容的长文；标题没有明确现行/历史状态。
- 文件日期不是结论顺序。同为 7-19 的“全阶段复盘”仍写 W0/W1 待做，稍后的 W1 报告已经 STOP。
- 7-19 Home 仍把 RHL 归一化、可靠性加权和集成列为未来重点，而负结果与新需求已经改变优先级。
- `v3plus设计与验证（未完善收尾）` 的名称已经过时，V3+ 主线集成早已完成。
- 文档写“路径存在”“全部复现通过”时往往指原 A100/TRS 现场；当前迁移目录并没有权重和全量日志。

## 2. 新人阅读顺序

| 时间预算 | 阅读 | 看完应知道什么 |

| 查实现时 | `代码理解与学习/训练逻辑详解：step_0输出与后续steps.md`，并对照源码 | realign、step0 来源与 step1 输出的区别 |

旧“新人版/导师版”保留为 7 月的阶段快照，不再作为最新状态入口。新入口只需要一个 `README.md`，不再维护多个互相抄写的 Home。

顶层只按“读者要找什么”分类；方法名不再同时散落于设计、结论、改动三棵树。**一个方法规格可以引用多个实验报告，实验报告不重新抄完整方法原理。** 历史提案在目录清单中暂映射到 `02_methods/history`；正式迁移时将已被取代版本收进相应 `90_archive` 子目录，并只保留一份现行规格。

`Codex_Plans/` 的 shell、TSV 队列、holdout txt/json 不应当普通文档搬走：runner 可能以相对路径读取它们。建议短期保留原位置，仅在新 INDEX 建立链接；后续专门把可执行实验资产迁入 `experiments/` 时再统一修改路径与验收。checkpoints 中的 JSON/manifest 继续与对应实验目录放在一起。

### 4.2 原理与方法参考

- 论文精读保留 **正文翻译**、**结构化精读**、**论文精读与思考分析报告**三种用途；“精读笔记”主要作个人阅读参考。它们可归同一个索引，日常入口只链接一篇。
- 两份数学文档分别保留“快速公式解释”和“完整推导”，避免重复扩写。
- 训练逻辑详解、6 月协议讲解、配置对照、Buffer 机制值得保留；过时模型 API 用当前代码校正。
- BOA/PGH/PowerNorm/CA-C-RLS 的 6-20 设计文档有方法储备价值，但每篇头部需明确“设计 / 部分实现 / 阴性 / 未实验”。
- 6-26 manifest 与 6-25 resume 报告作为工程追溯价值较高；把现行用法压缩进 runbook 即可。

## 6. 实施迁移的顺序

1. 固化本次快照、文档清单与实验账本；先确保师兄能从新入口阅读。
2. 先收拢**现行事实**：项目首页、分支状态、协议字典、方法状态表。历史正文暂不改写。
3. 按清单导出 branch-only 资产；同名不同 blob 按日期/commit 加后缀，不能覆盖。
4. 先搬纯 Markdown/图片，再单独处理可执行 plans；更新相对链接，检查文件路径。
5. 每个旧入口保留一行迁移指针，直到所有文档与脚本链接验证通过。
6. 最后才归档活动 branch、清理不需要的 worktree；分别审阅文档迁移和 Git 清理 diff。

目录简洁依赖“只有一份当前事实”，不依赖把所有历史压进一个巨大总结。建议以后每个方法只维护一行状态：**提案 → 实现 → 初筛 → 复核 → 保留/冻结**；每个状态转移附实验 ID 与决策日期。
