## 3. 伪标签路线为何归档

固定伪标签本身有收益；缺乏稳定额外收益的是类别自适应阈值与简单可靠性加权：

| 已完成比较 | 结果 | 判断 |
| --- | --- | --- |
| APT与总体分位点匹配的MG，全6组配对seed | APT−MG平均约+0.0020 pp | 类别阈值分配的独立贡献很小 |
| W1 confidence | overlap −0.0059、disjoint +0.0439 pp；平均+0.0190 pp | 方向不一致、收益不足 |
| W1 confidence×margin | overlap −0.0159、disjoint +0.0838 pp；平均+0.0339 pp | 旧新类权衡明显 |

W1为seed1筛选，未补充多seed稳定性验证；已有结果支持暂停该路线，不继续W2/W3。完整源码、teacher适配、校准、W0诊断与weighted C-RLS保存在归档tag。主线不增加这些策略开关和训练依赖。

## 4. 本轮定位并修复的问题

| 问题 | 复现与影响 | 修复 |
| --- | --- | --- |
| PyTorch完整模型checkpoint加载失败 | PyTorch2.8下原有checkpoint/resume测试报weights-only反序列化错误 | 项目完整模型加载显式使用weights_only=False；通用load_ckpt先映射CPU |
| 短step0训练保存崩溃 | 少于5轮、每轮不足100批时尚未验证，curr_score未赋值 | final保存已有best_score，未验证时为−1 |
| 短step0到step1衔接失败 | 尚无验证最优checkpoint时，step1只查命名best文件，忽略已有final.pth | 优先best；仅当best缺失且final存在时读取final |
| 默认step0指向旧V3 | 选择V3+仍默认BASE_SUBPATH=20260606 | 新run默认复用自身SUBPATH；已有base显式指定 |
| 旧TRS/RHL参数漂移 | TRS固定V3；两脚本不完整转发AIR source/clean协议，且依赖当前目录和python命令 | 改为共享run.sh的薄封装；保留各自GPU或归一化配方 |
| 迁移后数据/临时目录仍为旧绝对路径 | 默认数据与TMPDIR指向旧服务器 | run.sh默认仓库内VOC和/tmp，可由环境覆盖 |
| 无法关闭预训练 | PRETRAINED_BACKBONE空字符串被默认值替代 | 保留显式空值，并用参数数组传递 |
| STEP_INCREMENT=0可无限循环 | runner未检查增量步长 | 启动前检查正整数步长及有序步范围 |
| 解析头强制正方形输出 | 7×9特征还原为7×7时报reshape错误 | AIR传递真实H/W，保留旧直接调用的方形行为 |
| 全ignore批次解析拟合崩溃 | 所有label=255时，对空张量求max | 空有效像素批次保持原统计量并直接返回 |

这些修复不引入伪标签新策略、BOA初始化或集成训练。main既有的显式RHL集成评估工具保留为历史工具；普通训练路径不会自动调用它。旧`run_origin.sh`移入历史脚本目录。
